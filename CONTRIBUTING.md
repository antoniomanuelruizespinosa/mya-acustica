# Coordinación

1. Antonio decide requisitos. Revisión y Control verifica; Desarrollo implementa.
2. Leer `Documentacion/00_Guia_y_control/decisiones-visuales-aprobadas.txt` antes de modificar la interfaz. Las correcciones expresas posteriores prevalecen; las imágenes ilustrativas no sustituyen requisitos.
3. Un único editor de código por checkout. No cambiar ramas mientras otro chat escribe. Para trabajo simultáneo, usar worktrees separados coordinados.
4. Crear rama `mya-NNN-descripcion` desde el punto acordado. Commits pequeños con problema y resultado. No cambios ajenos al encargo.
5. Abrir pull request con pruebas, límites y revisión visual. No dar por implementado un motor a partir de botones o maquetas.
6. Revisión técnica y aceptación del usuario antes de integrar. No force-push ni borrar ramas o datos ajenos.
7. No subir secretos, sesiones personales, manuales propietarios, SDK, binarios ni preferencias de máquina. Revisar archivos staged antes del commit.
8. Registrar pendientes y decisiones en archivos compartidos. No reabrir decisiones confirmadas por iniciativa propia.

La regla de revisión es inicialmente de procedimiento; no implica protección técnica de GitHub hasta que conste su activación. No activar servicios de pago, despliegues ni publicaciones automáticas sin autorización.
